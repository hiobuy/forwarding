# v1.0.0 — Initial Public Release

> Published on 2026-10-18 as the [v1.0.0 GitHub Release](https://github.com/hiobuy/forwarding/releases/tag/v1.0.0).

## Project overview

HioBuy Forwarding is an open-source, self-hosted parcel forwarding and package consolidation platform. Operators run their own branded customer portal and admin console on Cloudflare Workers, set their own prices, and collect their own customer payments. Warehouse receiving, packing, and international shipping are done through the [HioBuy Fulfillment API](https://hiobuy.com/en/api-docs/fulfillment-setup).

HioBuy Forwarding is a customer business platform, not a warehouse management system.

## Core features

### HioBuy Fulfillment integration

- Warehouse address and destination sync
- Live channel quotes with your markup and exchange rate applied on the server
- Inbound notices from customer pre-alerts, and cancellation while a package is still `PENDING`
- Package and shipment status pulls, with conflict detection and a per-attempt log
- Shipment create, HioBuy Pay, cancel, intercept, and tracking
- Signed webhooks for package receipt and exceptions, shipment payment, dispatch, delivery, and exceptions, and low fulfillment balance
- Read-only fulfillment wallet balance and transactions

### Customer portal

- Email registration with verification, optional Google sign-in and Turnstile
- Personal warehouse address with member code
- Pre-alerts, claims, exception responses, and warehouse photos
- Consolidation, checkout, shipments, tracking, and shipping documents
- Address book, invoice details, notifications, and email preferences
- Optional assistant on Workers AI that asks before it changes anything

### Admin console

- Overview with queues, fulfillment progress, and gross profit
- Packages, shipments, customers, and manual wallet adjustments
- Staff roles (owner, manager, support) with per-route permissions
- Built-in Developer Guide at `/admin/guide`

### Payments and wallet

- USD customer wallet in integer cents
- Stripe Checkout for top-ups and freight, with signed webhooks and dispute tracking
- Bank transfer top-ups confirmed by an operator
- Customer payment and HioBuy fulfillment payment kept as separate ledgers

### Shipping calculator

- Public, customer, and admin calculators share one quote path
- Guests and customers never see cost or markup. Staff see cost and estimated profit

### Business customization

- Business name, logo, colors, support email, app domain, and public website URL
- Integrated public website or app-only mode
- Editable email templates, document numbering, invoicing, and tracking labels

## Deployment requirements

- Node.js 20 or newer
- A Cloudflare account with Workers, D1, R2, Durable Objects, and Workers AI
- A HioBuy developer account and a warehouse fulfillment API key. HioBuy subscriptions, warehouse services, and freight are billed by HioBuy
- SMTP credentials for email, and a Stripe account or bank account to collect payments

See the [README](../../README.md) and the [Production checklist](../getting-started/production.md).

## Known limitations

- Customers cannot request value-added warehouse services yet. HioBuy does not offer them.
- Commercial customs invoices are not generated.
- The HioBuy fulfillment wallet cannot be topped up from this app.
- Webhooks do not replace a manual pull from HioBuy.
- The built-in quote rate limit is per Worker isolate. Add Cloudflare rate limiting for a hard limit.
- The HioBuy API key saved in the admin is stored unencrypted in D1.- Databases created before this release must be recreated, because migrations were squashed.
